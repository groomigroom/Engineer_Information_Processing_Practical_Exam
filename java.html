    private T t;

    public T getField() {
        return t;
    }

    public void setField(T t) {
        this.t = t;
    }

    public  Class getClassType(E e) {
        return e.getClass();
    }

    public static  T returnParamObj(T t) {
        return t;
    }
}

public class Main {

    public static void main(String[] args) {

        GenericClass c1 = new GenericClass<>();
        c1.setField("TEST");
        System.out.println("class1 value > : " + c1.getField());

        c2.setField(3.141592);

/*
@Override 의 의미재정의 표시: 부모(Object) 클래스가 물려준 메서드를 그대로 쓰지 않고, 내가 새로 만들어서 덮어쓰겠다는 선언입니다.컴파일러 체크: 개발자가 실수로 메서드 이름을 틀리면(tostring 등) 컴파일러가 에러를 발생시켜 실수를 방지해 줍니다.2. public String toString() 의 의미자바에서 System.out.println(p1.info)와 같이 객체를 출력문 안에 넣으면, 자바는 내부적으로 그 객체의 .toString() 메서드를 자동으로 호출합니다.즉, p1.info를 출력하는 행위는 p1.info.toString()을 실행하는 것과 같습니다.3. return String.valueOf(this.rank); 의 의미원래 this.rank는 숫자(int)형 데이터입니다.toString() 메서드는 무조건 문자열(String)을 반환해야 하므로, String.valueOf()를 사용해 숫자 형태인 등급(rank)을 문자열로 변환하여 반환해 준 것입니다.

@Override 어노테이션(Annotation)을 지우고 public String toString()만 작성해도 출력값은 똑같이 제대로 나옵니다.@Override는 기능적인 소스코드가 아니라, 컴파일러와 다른 개발자에게 정보를 전달하는 '표시(주석)' 역할을 하기 때문입니다.지워도 똑같이 작동하는데 왜 굳이 쓰는지, 그 중요한 이유 2가지를 알려드립니다.💡 @Override를 쓰는 이유1. 철자 실수 방지 (가장 중요)만약 개발자가 실수로 대소문자를 틀려 tostring()이라고 적었다고 가정해 보겠습니다.@Override가 없을 때: 자바는 에러를 내지 않고 그냥 "새로운 메서드를 만들었구나" 하고 넘어갑니다. 하지만 프로그램은 Object 클래스의 원래 toString()을 호출하므로, 화면에는 다시 EmployeeInfo@7a81197d 같은 주소값이 출력되는 버그가 발생합니다. 원인을 찾기 힘들어집니다.@Override가 있을 때: 자바 컴파일러가 빨간 줄(에러)을 띄우며 "부모 클래스에 그런 메서드가 없는데 왜 재정의한다고 하니?"라고 즉시 알려줍니다.2. 코드의 가독성 향상다른 개발자가 내 코드를 읽을 때, @Override가 붙어 있으면 "아, 이 메서드는 이 클래스에서 새로 만든 게 아니라 부모 클래스나 인터페이스에서 물려받아 기능을 바꾼 거구나" 하고 바로 이해할 수 있습니다.

    public static void swap(int[] arr, int idx1, int idx2){
        int temp = arr[idx1];
        arr[idx1] = arr[idx2];
        arr[idx2] = temp; // ← (1): idx2
    }

    public static void Usort(int[] array, int length){
        for (int i = 0; i < length; i++) {
            for (int j = 0; j < length - i - 1; j++) {
                if (array[j] > array[j + 1]) {
                    swap(array, j, j + 1);
                }
            }
        }
    }

    public static void main(String[] args) {

        int nx = 6; 
        Usort(item, nx); //

    }
}

제시해주신 코드 내부의 new Collection<>(0)에서 사용된 <>의 의미는 **다이아몬드 연산자(Diamond Operator)**라고 하며, **제네릭 타입 추론(Generic Type Inference)**을 수행합니다.
자바 컴파일러가 앞의 선언이나 생성자에 전달된 인수를 보고 타입을 자동으로 알아내기 때문에, 꺾쇠괄호 안의 타입을 생략할 수 있게 해주는 기능입니다.

* 원래 표현: new Collection(0)라고 적어야 합니다. 컴파일러가 매개변수 0을 보고 Integer 타입임을 알기 때문입니다.
* 생략 표현: <>만 적어주면 컴파일러가 인자의 실제 타입(0 $\rightarrow$ Integer)을 추론하여 Collection로 알아서 처리합니다.

------------------------------
## ⚠️ 주의할 점: 위 코드의 실행 결과는 'B0'입니다
이 코드에서 print() 메서드가 실행될 때 오버로딩(Overloading) 규칙에 의해 A0이나 C0이 출력될 것 같지만, 실제로는 B0이 출력됩니다.

Collection에서 는 상한선(Bounded wildcard)이 지정되지 않았으므로, 컴파일 이후 일반 Object 타입으로 변환됩니다. 따라서 new Printer().print(value);를 호출할 때 value 변수의 컴파일 시점 타입은 Object가 되어 print(Object a) 메서드가 매칭됩니다.
------------------------------
이 제네릭 타입 소거(Type Erasure) 과정이나, 원하는 타입(Integer, Number)으로 올바르게 메서드를 호출하는 해결 방법이 궁금하시면 말씀해 주세요. 구체적인 예시 코드로 설명해 드리겠습니다.

    public static void main(String[] args) {
        String str = "abacabcd";
        boolean[] seen = new boolean[256];
        System.out.print(calculFn(str, str.length() - 1, seen));
    }

    public static String calculFn(String str, int index, boolean[] seen) {
        if (index < 0) return "";

        char c = str.charAt(index);
        //charAt()은 문자열(String)에서 특정 위치(인덱스)에 있는 문자(char)를 하나만 추출할 때 사용하는 메서드입니다.
        String result = calculFn(str, index - 1, seen);
        /*
        index 6에서 index 0까지 호출
        */

        if (!seen[c]) {
            seen[c] = true;
            return result + c;  // ← 현재 문자를 뒤에 붙이기
        }
        //abcd만 붙어짐. 

        return result;
    }
}

public class Main {
    public static void main(String[] args) {
        int sum = 0;
        try {
            func();  // NullPointerException 발생
        } catch (NullPointerException e) {
            //NullPointerException(NPE)은 '아무것도 참조하고 있지 않은 상태(null)'의 객체에 접근하거나 조작하려 할 때 발생하는 런타임 예외입니다.
            sum = sum + 1;  // 이 블록이 실행됨
        } catch (Exception e) {
            //Exception(예외)이란, 프로그램 실행 중에 개발자의 실수나 사용자의 잘못된 조작 등으로 인해 발생하는 예기치 못한 오류를 말합니다.
            sum = sum + 10; // 이 블록은 실행되지 않음
            //첫 번째 매칭에서 종료 (위에서 아래로 검사)자바는 예외가 발생하면 catch 블록을 위에서부터 순서대로 검사합니다.func()에서 NullPointerException이 던져졌을 때, 가장 위에 있는 catch (NullPointerException e)가 이를 정확히 잡아냈습니다.예외를 한 번 잡으면 나머지 catch 블록들은 모두 건너뛰고 실행을 종료합니다.
        } finally {
            sum = sum + 100; // 무조건 실행
        }
        System.out.print(sum);  // 결과 출력
        //101
        
    }

interface Number {
    //인터페이스(Interface)는 클래스가 반드시 구현해야 하는 '설계도'이자 '표준 규약'입니다. 객체가 어떤 동작을 해야 하는지 껍데기(메서드 시그니처)만 정의하고, 구체적인 동작 내용은 인터페이스를 구현하는 클래스에서 작성합니다
    int sum(int[] a, boolean odd); // odd가 true면 홀수 합, false면 짝수 합
}

class ODDNumber implements Number {
    //implements는 클래스가 인터페이스(Interface)를 구현할 때 사용하는 키워드입니다. 인터페이스에 정의된 추상 메서드를 클래스가 물려받아 실제 작동하는 코드({})로 완성(구현)하도록 강제하는 역할을 합니다.
    public int sum(int[] a, boolean odd) {
        int result = 0;
        //a.length == 9
        for (int i = 0; i < a.length; i++) {
            //i = 0 ==> 0 < 9
            if ((odd && a[i] % 2 != 0) || (!odd && a[i] % 2 == 0)) {
                result += a[i];
            }
            //true && a[0] % 2 != 0 ==> true ===> result += a[0] ==> result = 1
            //i = 1 ==> 0 < 9
            //true && a[1] % 2 == 0 ==> false , false //
            //i = 2 ==> 0 < 9
            //true && a[2] % 2 != 0 ==> true ===> result += a[2] ==> result = 4
            //i = 3 ==> 0 < 9
            //true && false , false //
            //i = 4 ==> 0 < 9
            //true && true ===> result += a[4] ===> result = 9 ===> 7과 9도 더하면 25
            
            //i = 0 ==> 0 < 9
            //false || true && false ====> 짝수일 때만 가능함. ===> 2, 4, 6, 8 더하면 ===> 20
         }
        return result;
    }
}

    }
}

    public int compute (int num) {
        if (num <= 1) return num;
        return compute(num - 1) + compute(num - 2);
    }
}

    @Override
    public int compute(int num) {
        //compute(4)

        //compute(4) ==> compute(3) + compute(1) ==> compute(2) + compute(0) + compute(1) ==> compute(1) + compute(-1) + compute(0) + compute(1) ==> 1
        return compute(num - 1) + compute(num - 3);
    }
}

        System.out.print(obj.compute(4));

class Time {
  boolean am;
  int hour;
  int minute;
  int second;
  
  Time(boolean am, int hour, int minute, int second) {
    this.am = am;
    this.hour = hour;
    this.minute = minute;
    this.second = second;
  }
  
  void whatTime() {
    System.out.print(am ? "오전" : "오후");
    System.out.println(hour + "시" + minute + "분" + second + "초");
  }
}

class Main {
  public static void main(String[] args) {
    Time now = new Time(true, 12, 34, 56);
    now.whatTime();
    //오전12시34분56초
  }
}

/*
제시된 자바 코드에서 this 키워드를 사용하는 핵심 이유는 매개변수(Parameter)와 멤버 변수(Field)의 이름이 같을 때 발생하는 이름 충돌을 해결하기 위함입니다.상세한 이유와 작동 원리는 다음과 같습니다.1. 이름이 같을 때 변수 은닉(Shadowing) 발생Time 생성자 정의를 보면, 입력받는 매개변수 이름(am, hour, minute, second)과 클래스가 가진 멤버 변수 이름이 정확히 일치합니다.자바는 블록 안에서 이름이 같으면 더 가까운 변수(이 경우 매개변수)를 우선시합니다.따라서 this 없이 hour = hour;라고 쓰면 멤버 변수가 아니라 매개변수 자기 자신에게 값을 다시 대입하는 의미 없는 코드가 됩니다.2. this의 역할과 작동 방식this는 메서드나 생성자를 호출한 현재 객체 자신을 가리키는 참조 변수입니다.변수 앞에 this.을 붙이면 자바 컴파일러에게 "이것은 매개변수가 아니라 이 객체의 멤버 변수다"라고 명확히 알려주게 됩니다.this.hour = hour; 코드는 **"현재 객체의 멤버 변수 hour에 매개변수로 들어온 hour 값을 넣겠다"**는 의미가 됩니다.3. this 사용의 장점클래스의 속성을 정의하는 멤버 변수 명칭을 생성자에서도 그대로 유지할 수 있습니다.데이터의 가독성이 높아지며, 변수의 목적이 명확해져 유지보수가 쉬워집니다.코드가 정상적으로 동작하게 만드는 과정이나 자바의 다른 키워드에 대해 더 알고 싶으시다면, 아래 항목 중 진행하고 싶은 작업을 알려주세요:이 클래스에 객체를 생성하는 다른 형태의 생성자(Overloading) 추가법자바에서 this의 또 다른 용도인 this() 생성자 호출법클래스의 변수를 안전하게 숨기는 접근 제어자(private)와 Getter/Setter 적용법

  }

    for (int i = 1; i < num; i++) {
      if (num % i == 0) {
        sum += i;
      }
    }
  }
  
  public int getSum() {
    return sum;
  }
}

  public static void main(String[] args) {

  }
}

    유지보수성의 향상 : 클래스를 사용하면 관련 있는 코드를 논리적으로 그룹화하여 구조적으로 정리할 수 있습니다. 이렇게 구조화된 코드는 유지보수가 쉬워집니다. 즉, 클래스를 사용하면 코드의 가독성과 유지보수성이
    향상됩니다.
    코드의 안정성 : 각 클래스는 자체적으로 캡슐화되어 있어 다른 클래스와 독립적으로 작동합니다. 클래스는 자신의 메서드와 속성만을 외부에서 접근할 수 있게 제한할 수 있기 때문에, 코드의 안정성이 향상됩니다.

JVM(Java Virtual Machine)이 프로그램을 실행할 때 가장 먼저 호출하는 필수 시작점입니다. public static void main(String[] args) 구조를 가지며, 객체 생성
    없이 실행되고 프로그램의 전체 흐름을 제어하는 진입점 역할을 합니다.주요 특징 및 의미프로그램 시작점: main 메서드가 없으면 자바 어플리케이션은 실행되지 않습니다.JVM에 의한 호출: 프로그램 실행 시
    JVM은 제일 먼저 이 메서드를 찾아 실행합니다.public: 외부(JVM)에서 어디서든 호출 가능해야 하므로 접근 제한자가 public입니다.static: 객체를 생성하지 않아도 메모리에 올라가, JVM이
    인스턴스화 없이 바로 호출할 수 있습니다.void: 실행 후 종료 시 호출자(JVM)에게 반환할 값이 없음을 의미합니다.String[] args: 실행 시 외부에서 매개변수(인자)를 받을 수 있는 문자열

    영역)에 고정되어 프로그램 종료 시까지 유지되며, 모든 인스턴스가 하나의 값을 공유합니다
