class A {
    String f(Object x) { return "1"; }
    String g() { return f("a"); }
}
class B extends A {
    String f(Object x) { return "2"; }
    String f(String x) { return "3"; }
}
public class Main {
    public static void main(String[] args) {
        A a = new B();
        System.out.println(a.g());
    }
}
/*
질문하신 내용이 자바를 배울 때 가장 많이 헷갈리는 반전 포인트입니다. 결론부터 말씀드리면, "a"가 String임에도 불구하고 f(String x)가 실행되지 않습니다.
이유는 f("a") 코드가 작성된 위치가 A 클래스 내부이기 때문입니다. 자바 컴파일러의 작동 순서를 따라가 보면 그 이유를 명확히 알 수 있습니다.
------------------------------
## 1. 컴파일러는 A 클래스 안만 보고 결정합니다
f("a")가 실행되는 g() 메서드는 어디에 적혀있나요? 바로 A 클래스 안에 있습니다.

class A {
    String f(Object x) { return "1"; }
    String g() { return f("a"); } // <- 바로 여기!
}

자바 컴파일러가 이 코드를 읽고 조립(컴파일)할 때, A 클래스 내부만 바라봅니다.

* 컴파일러: "g() 안에서 f라는 메서드를 호출하네? 인자가 "a"(String)구나."
* 컴파일러: "A 클래스 안에 String을 받을 수 있는 f 메서드가 어디 있나 찾아보자."
* 컴파일러: "f(String)은 없고, f(Object) 하나 있네! String은 Object에 들어갈 수 있으니까(다형성) 여기로 연결해야겠다."

이 시점에는 하위 클래스인 B에 f(String)이 존재한다는 사실을 컴파일러가 아예 모릅니다. 그래서 코드가 실행되기도 전에 이 호출문은 f(Object)를 실행하라고 낙찰되어 버립니다.
## 2. 런타임에는 '오버라이딩'된 것만 바꿔치기할 수 있습니다
프로그램이 실행되면 A a = new B();에 의해 실제 메모리에는 B 객체가 들어섭니다. 그리고 a.g()가 호출되어 A 클래스에 정의된 g()가 실행됩니다.
g() 안에서 아까 낙찰된 f(Object)를 실행하려는 순간, 자바는 실제 메모리에 있는 B 객체를 들여다봅니다.

* 자바: "컴파일러가 f(Object) 실행하라고 했어. 혹시 B가 f(Object)를 오버라이딩(재정의) 했니?"
* B 클래스: "네! 여기 String f(Object x) { return "2"; }로 재정의해 뒀습니다!"
* 자바: "오케이, 그럼 1번 대신 2번을 실행할게!"

이때 B 클래스에 있는 String f(String x) { return "3"; }은 이름만 같을 뿐, 컴파일러가 지정한 f(Object)와는 완전히 다른 메서드(오버로딩)입니다. 따라서 런타임에 갈아끼우는 대상(오버라이딩)이 될 수 없어 무시됩니다.
------------------------------
## 💡 만약 "3"이 출력되게 하려면?
g() 메서드를 A가 아니라 B 클래스 안에서 호출하거나, g() 메서드 자체를 B에서 오버라이딩해야 합니다.

public class Main {

        Base a = new Derivate();  // 업캐스팅 (다형성)
        Derivate b = new Derivate();

        System.out.print(a.getX() + a.x + b.getX() + b.x);
        //52
    }
}

class Base {
    int x = 3;
    //3 a.x

    int getX() {
        return x * 2;
    }
}

class Derivate extends Base {
    int x = 7;
    // b.x 7

    int getX() {
        return x * 3;
    }
    //21 a.getX()
    //21 b.getX()
}

제시하신 자바 코드는 메서드 오버라이딩(다형성)과 멤버 변수(필드)의 은닉(Hiding) 원리에 의해 작동합니다.
결론부터 말씀드리면 출력 결과는 41입니다. 이 결과가 나오는 원리를 세부적으로 설명해 드립니다.
## 1. 핵심 작동 원리

* 메서드는 실행 시점(Runtime)에 결정됩니다.
* 참조 변수의 타입이 부모(Base)일지라도, 실제 생성된 객체가 자식(Derivate)이라면 자식 클래스의 오버라이딩된 메서드가 호출됩니다. 이를 다이나믹 바인딩(Dynamic Binding)이라고 합니다.
* 변수는 컴파일 시점(Compile time)에 결정됩니다.
* 자식 클래스에서 부모 클래스와 동일한 이름의 변수를 선언하면 부모의 변수가 숨겨집니다(은닉).
   * 변수에 접근할 때는 참조 변수의 타입을 따라갑니다. 부모 타입 변수로는 부모의 x에, 자식 타입 변수로는 자식의 x에 접근합니다. [1, 2, 3, 4, 5]

* Derivate의 getX()는 자신의 x(7) * 3을 수행하여 21을 반환합니다. [6] 

## a.x $\rightarrow$ 3

* a의 참조 타입은 Base입니다.
* 변수는 참조 타입을 따르므로 Base 클래스에 선언된 x에 접근합니다.
* 따라서 Base의 x 값인 3을 가져옵니다.

## b.getX() $\rightarrow$ 21

* b는 Derivate 타입이고 실제 객체도 Derivate입니다.
* Derivate 클래스의 getX()가 호출됩니다.
* 자신의 x(7) * 3을 수행하여 21을 반환합니다.

## b.x $\rightarrow$ 7

* b의 참조 타입은 Derivate입니다.
* 변수는 참조 타입을 따르므로 Derivate 클래스에 선언된 x에 접근합니다.
* 따라서 Derivate의 x 값인 7을 가져옵니다.

                System.out.print("N");

class MyObj {
  int value = 0;
  void count(MyObj c) {
    c.value = c.value + 100;
  }
}
public class Main {
  public static void main(String[] args) {
    MyObj test = new MyObj();
    System.out.println(test.value);
    test.count(test); //여기가 빈칸 채우기
    System.out.println(test.value);
  }
}
/*
test.count(test);에서 매개변수로 전달되는 (test)의 실제 값은 객체의 메모리 주소(참조값)입니다.자바의 메모리 구조와 동작 원리로 보면 다음과 같습니다.1. 실제 전달되는 값: 참조값 (Reference)MyObj test = new MyObj();가 실행되면 메모리(Heap 영역)에 실제 객체가 생성됩니다.변수 test는 그 객체가 어디 있는지 가리키는 메모리 주소(참조값)를 가지고 있습니다.따라서 (test)를 넣는 것은 "이 객체의 주소를 보낼 테니 찾아가라"는 뜻입니다.2. 메서드 내부에서의 동작count(MyObj c) 메서드가 호출되면, 매개변수 c는 test가 주었던 똑같은 메모리 주소를 복사받습니다.결국 c와 test는 메모리상에서 동일한 하나의 객체를 가리키게 됩니다.이 때문에 c.value = c.value + 100;을 하면 실제 test 객체의 value가 100으로 바뀝니다.쉽게 비유하자면, test는 실제 집(객체)이 아니라 "집 주소가 적힌 종이"입니다. 메서드에 종이를 복사해서 넘겨주었기 때문에, 메서드 안에서도 그 주소를 보고 찾아가서 집을 수리(값 변경)할 수 있는 것입니다.

    }

            b = a * i + b;
        }
        return a + b;
    }

        obj.a = 5; 
        int b = obj.func();
        System.out.print(obj.a + b); 
        //5 + 56 == 61
    }

      }
    }
  }
  
  public int getSum() {
    return sum;
  }
}

    유지보수성의 향상 : 클래스를 사용하면 관련 있는 코드를 논리적으로 그룹화하여 구조적으로 정리할 수 있습니다. 이렇게 구조화된 코드는 유지보수가 쉬워집니다. 즉, 클래스를 사용하면 코드의 가독성과 유지보수성이
    향상됩니다.
    코드의 안정성 : 각 클래스는 자체적으로 캡슐화되어 있어 다른 클래스와 독립적으로 작동합니다. 클래스는 자신의 메서드와 속성만을 외부에서 접근할 수 있게 제한할 수 있기 때문에, 코드의 안정성이 향상됩니다.

JVM(Java Virtual Machine)이 프로그램을 실행할 때 가장 먼저 호출하는 필수 시작점입니다. public static void main(String[] args) 구조를 가지며, 객체 생성
    없이 실행되고 프로그램의 전체 흐름을 제어하는 진입점 역할을 합니다.주요 특징 및 의미프로그램 시작점: main 메서드가 없으면 자바 어플리케이션은 실행되지 않습니다.JVM에 의한 호출: 프로그램 실행 시
    JVM은 제일 먼저 이 메서드를 찾아 실행합니다.public: 외부(JVM)에서 어디서든 호출 가능해야 하므로 접근 제한자가 public입니다.static: 객체를 생성하지 않아도 메모리에 올라가, JVM이
    인스턴스화 없이 바로 호출할 수 있습니다.void: 실행 후 종료 시 호출자(JVM)에게 반환할 값이 없음을 의미합니다.String[] args: 실행 시 외부에서 매개변수(인자)를 받을 수 있는 문자열

    영역)에 고정되어 프로그램 종료 시까지 유지되며, 모든 인스턴스가 하나의 값을 공유합니다
