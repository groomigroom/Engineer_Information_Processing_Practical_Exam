class Stack:
    def __init__(self):
        self.stack = list()
    def __len__(self):
        return len(self.stack)
    def push(self, x):
        self.stack.append(x)
    def pop(self):
        return self.stack.pop()

stack = Stack()

print(bool(stack))  # False

stack.push(100)     # 100 입력

print(bool(stack))  # True

def f(a) :
    m = [[x] for x in a]
    #m = [[1], [2], [3], [4]]
    b = m[:]
    #b = [[1], [2], [3], [4]]
    for i in range(len(b) - 1) :
        b[i + 1] += b[i]
    #b[1] == [2, 1]
    #b[2] == [3, 2, 1]
    #b[3] == [4, 3, 2, 1]
    return sum(len(x) for x in m)
    #1 + 2 + 3 + 4 == 10
print(f([1, 2, 3, 4]))
"""
m이 b와 동일하게 변하는 이유는 b = m[:]가 **얕은 복사(Shallow Copy)**이기 때문입니다.b = m[:]를 하면 겉모습(가장 바깥쪽 리스트)은 복사되어 서로 다른 객체가 되지만, 그 내부의 서브 리스트들([1], [2] 등)은 실제 값을 복사한 것이 아니라 같은 메모리 주소를 가리키는 참조(주소) 상태를 유지합니다.이로 인해 발생하는 현상을 단계별로 설명해 드리겠습니다.1. 초기 주소 공유 상태b = m[:]가 실행된 직후, 두 변수의 메모리 구조는 다음과 같습니다.m ➔ [ 주소A, 주소B, 주소C, 주소D ]b ➔ [ 주소A, 주소B, 주소C, 주소D ]인덱스실제 메모리에 존재하는 리스트 객체m에서의 참조b에서의 참조0 (주소A)[1]m[0]이 가리킴b[0]이 가리킴1 (주소B)[2]m[1]이 가리킴b[1]이 가리킴2 (주소C)[3]m[2]이 가리킴b[2]이 가리킴3 (주소D)[4]m[3]이 가리킴b[3]이 가리킴2. 반복문에서의 수정 (+= 연산의 비밀)반복문 안에서 b[i + 1] += b[i] 연산이 수행될 때, 파이썬 리스트의 += 연산은 **새로운 리스트를 만들지 않고 기존 리스트의 메모리 주소를 그대로 유지한 채 내부 데이터만 수정(In-place modification)**합니다.i = 0 일 때: b[1] += b[0]b[1]이 가리키는 주소B의 리스트([2])에 b[0]의 내용([1])이 추가되어 **[2, 1]**이 됩니다.이때 m[1]도 여전히 주소B를 가리키고 있으므로, m[1]을 확인해도 [2, 1]로 바뀌어 있습니다.i = 1 일 때: b[2] += b[1]b[2]가 가리키는 주소C의 리스트([3])에 현재 b[1]의 내용([2, 1])이 추가되어 **[3, 2, 1]**이 됩니다.마찬가지로 m[2]도 주소C를 가리키고 있으므로 똑같이 수정됩니다.3. 최종 결론결과적으로 b 내부의 원소들을 수정했지만, 그 원소들이 저장된 메모리 공간(주소A~D)을 m도 똑같이 공유하고 있었기 때문에 m도 b와 완벽히 같은 값으로 변하게 됩니다.따라서 코드 마지막 줄의 sum(len(x) for x in m)을 계산할 때 m은 [[1], [2, 1], [3, 2, 1], [4, 3, 2, 1]] 상태이므로 각 길이를 더한 **1 + 2 + 3 + 4 = 10**이 반환됩니다.
"""

class parent :
  def __init__(self) :
    print("parent 생성자")
  def __del__(self) :
    print("parent 소멸자")
  def show(self) :
    print("sunny")

class child(parent) :
  def show(self) :
    print("snow")
    
a = child()
a.show()
del a

"""
제시해주신 파이썬 코드는 클래스 상속, 메서드 오버라이딩, 객체 생명주기(생성자와 소멸자)의 원리로 작동합니다.실행 순서에 따른 구체적인 원리는 다음과 같습니다.1. 객체 생성 및 상속 (a = child())메모리 할당: child()가 호출되면 메모리에 child 클래스의 인스턴스(객체)가 만들어집니다.부모 생성자 호출: child 클래스 내부에는 생성자(__init__)가 정의되어 있지 않습니다. 파이썬은 상속 관계인 부모(parent) 클래스로 올라가 parent.__init__(self)를 대신 실행합니다.출력: "parent 생성자"가 화면에 출력됩니다.2. 메서드 오버라이딩 (a.show())메서드 탐색: a.show()를 호출하면 파이썬은 먼저 자식인 child 클래스에서 show 메서드를 찾습니다.재정의(Overriding) 적용: child 클래스에 show가 이미 정의되어 있으므로, 부모의 show는 무시하고 자식의 메서드를 실행합니다. 이를 메서드 오버라이딩이라고 합니다.출력: "snow"가 화면에 출력됩니다. class T :
  def __init__ (self, width, height) :
    self.width = width
    self.height = height
  def area(this) :
    a = this.width * this.height / 2
    return a
    
tt = T(4, 4)
print(tt.area())
"""
__init__ 의 의미__init__은 파이썬 클래스의 생성자(Constructor) 메서드입니다.자동 실행: 클래스로 새로운 객체(인스턴스)를 만들 때 자동으로 호출됩니다.역할: 객체가 생성되자마자 변수(width, height)를 초기화하고 값을 할당합니다.코드 예시: tt = T(4, 4)를 실행하는 순간 __init__이 실행되어 가로 4, 세로 4의 값을 가진 객체가 만들어집니다.📌 this 의 의미this는 메서드가 호출된 객체 자신을 가리키는 변수입니다.관례와의 차이: 파이썬에서는 일반적으로 이 첫 번째 매개변수 이름으로 self를 사용합니다.동작 원리: 파이썬은 문법적으로 첫 번째 매개변수를 무조건 객체 자신으로 인식합니다. 따라서 this라고 적어도 self와 똑같이 작동합니다.역할: tt.area()를 호출하면 this는 tt 객체 자체가 되므로, tt가 가진 width(4)와 height(4)에 접근할 수 있게 됩니다.
